# Purpose

用于快速总结一组代码 diff，帮助阅读者在不逐行细看的前提下理解改动目的、主要变化、影响范围与后续关注点。

# Instructions

1. 先按文件和模块归纳改动，再提炼整体主题。
2. 区分“做了什么”和“为什么这样改”，避免只复述表层 diff。
3. 如果改动涉及行为变化，要明确说明可能影响的用户路径或系统模块。
4. 对删除、重构、重命名、配置变更等不同类型改动分别说明。
5. 如发现高风险变化，单独标出需要重点关注的部分。

# Focus

- 本次改动的核心目标
- 涉及哪些模块、文件或职责边界
- 是否有接口、配置、行为层面的变化
- 是否可能带来回归风险或联动影响
- 阅读者接下来应重点查看什么

# Output

请按以下结构输出：

1. 一句话总结
2. 主要改动点
3. 影响范围
4. 风险与注意事项
5. 建议进一步查看的部分

# Constraints

- 不要简单逐文件翻译 diff。
- 不要忽略行为变化带来的实际影响。
- 不要夸大风险，也不要漏掉关键联动点。
- 总结要尽量压缩信息噪音，突出重点。
