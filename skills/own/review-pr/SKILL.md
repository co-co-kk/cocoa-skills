# Purpose

用于对 Pull Request 或一组待合并改动进行结构化审阅，帮助快速识别改动意图、潜在风险、缺失验证和可执行建议。

# Instructions

1. 先理解本次变更的目标、范围和上下文，不要脱离 diff 做结论。
2. 按“功能正确性、可维护性、回归风险、测试覆盖、用户影响”几个维度进行检查。
3. 优先指出真正影响质量的问题，避免把纯风格偏好当作核心问题。
4. 如果信息不足，明确说明缺少哪些上下文，而不是臆测实现意图。
5. 输出建议时，尽量给出可执行的修复方向或验证方式。

# Focus

- 变更是否实现了预期目标
- 是否引入明显 bug、边界遗漏或兼容性问题
- 是否存在过度复杂、职责不清或难维护的实现
- 是否缺少必要测试、文档或回归验证
- 是否存在值得重点关注的风险点

# Output

请按以下结构输出：

1. 变更概览
2. 主要风险点
3. 建议修改项
4. 建议补充的验证或测试
5. 审阅结论

# Constraints

- 不要在未确认上下文的情况下武断下结论。
- 不要把无关紧要的格式问题放在高优先级位置。
- 不要只罗列问题，要尽量说明为什么是问题。
- 如果改动整体合理，也要明确说明风险较低的依据。
